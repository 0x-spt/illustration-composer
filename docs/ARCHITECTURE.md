# Архитектура

10 предметов из Figma, у каждого два состояния (главный и фоновый) и две детализации (L и S). Сервис их не рисует и не меняет: только копирует, раскладывает и перекрашивает.

```
Figma ──(REST API или dev-плагин)──▶ scripts/library-sync ──▶ packages/library (в git)
                                                                    │
                                     packages/core ◀────────────────┘
                                     │          │
                              apps/web       server → api/compose-intent.js ──▶ Claude Haiku
```

- Библиотека выгружается из Figma один раз и коммитится. В рантайме Figma не нужна.
- `packages/core` — чистый TypeScript без React и DOM. Его используют и редактор, и серверная функция.

## Хранение

`packages/library/data/manifest.json` — описание каждого ассета:

- размеры и `viewBox`. У предмета есть `nominalWidth` (его L-ширина), от неё считается размер на холсте, поэтому пропорции между предметами всегда как в Figma;
- `colorMap`: исходный hex → место палитры (`bg1`…`paper`). Цвета, которых нет в палитре, привязываются к ближайшему месту по ΔE ≤ 8 (D2);
- `stacking`: может ли на предмете что-то лежать (`surface`) и может ли он сам лежать на другом (`flat`, `standing`).

Рядом лежат SVG предметов и декора, палитры, шаблоны раскладки, снятые с примеров дизайнера, каталог смыслов для подбора и силуэты предметов (`masks.json`) для проверки наложений.

При выгрузке SVG проходят через SVGO с выключенными плагинами, которые трогают геометрию и точность. Все `id` внутри получают префикс ассета, чтобы градиенты и маски разных файлов не пересекались. L и S — отдельные файлы, на холсте обе версии растягиваются до одной ширины, так что смена детализации меняет только рисунок.

## Извлечение

`getAsset(lib, ref, detail)` отдаёт файл по ссылке узла и детализации. Если такого нет, бросает ошибку, а не подсовывает другой. В браузере каждый SVG — отдельный чанк. Детализация S подгружается, только когда на неё переключились.

## Переиспользование

Узел сцены — `<g transform="translate rotate scale">` с inline-копией разметки ассета. `<use>` и ссылки на внешние файлы не используются, чтобы экспорт был самодостаточным.

- `scopeIds` добавляет к id суффикс узла, поэтому два одинаковых предмета на холсте не делят градиенты.
- `recolorMarkup` меняет только `fill`, `stroke` и `stop-color`: исходный hex → место → цвет целевой палитры. Пути не трогаются.
- Холст и экспорт рендерят узел одной функцией. Что видно в редакторе, то и попадает в файл.

## Цвет

Палитра — 8 мест: три фона, три цвета объектов, контур и белый. Встроенные схемы хранятся как данные. Свою палитру можно загрузить как JSON, список hex или `.ase`, цвета раскладываются по местам автоматически, раскладку можно поправить руками.

В фоне и у фоновых предметов цвета объектов запрещены. Это обеспечивает сама библиотека (в их `colorMap` нет мест `obj*`), а `validateScene` перед экспортом ещё раз проверяет сцену.

## Раскладка

- Шаблон — композиция из примера дизайнера: места с ролью (hero, support, backdrop), центром и порядком слоёв. Самый широкий главный предмет становится hero (D4).
- Размер сцены задаётся масштабом шаблона (D3), отдельного масштаба у предмета нет. Если предметы не помещаются, сцена уменьшается, но не меньше 0,6 от примера (D5).
- Краем кадра можно обрезать только плоские поверхности (книгу, папку, кошелёк). Hero виден минимум на 50–60 %, как в примерах (D6). Остальное остаётся целым.
- Наложения проверяются по силуэтам, а не по рамкам (D13): у дизайнера телефон лежит на книге с перекрытием рамок 96 %. На поверхность можно положить плоский предмет не больше 35 % её площади, остальные пары держат зазор. Если пара сталкивается, меньший предмет сдвигается, если не помогает — сцена уменьшается. Тест проходит все 495 сочетаний по 2–3 предмета в трёх форматах: разводятся 494.
- Декор подложки привязан к углам кадра и не зависит от масштаба сцены (D7).
- «Другой вариант» перебирает шаблоны и варианты подбора без нового запроса к модели.

## Подбор предметов

Оба сценария дают один и тот же интент: список `{ item, state, role }`.

- **По фразе.** Функция `/api/compose-intent` вызывает Claude Haiku со structured output. Предмет в схеме — enum из 10 id, так что несуществующий модель вернуть не может. Таймаут 12 секунд, ограничение 10 запросов в минуту на IP. Если ключа нет, модель отказала или API недоступен, подбор идёт офлайн по каталогу смыслов. Пустого холста не бывает.
- **По названиям.** Без модели: словоформы, синонимы, опечатки. На незнакомое слово сервис предлагает похожий предмет.

## Проверки

- Пути не меняются ни при выгрузке, ни при экспорте: тесты сравнивают атрибуты `d` до и после.
- Id в экспорте уникальны, все ссылки внутри файла находятся.
- В экспорте нет `<style>`, CSS-переменных, растра и `foreignObject`, у каждого предмета своя группа `<g id data-item data-state>`.
- Фон не содержит цветов объектов.
- Своя палитра проходит проверку: принимаются только `#RRGGBB`.
- E2E на production-сборке: фраза → холст → «Другой вариант» → смена палитры → скачанный SVG. И отдельный прогон на телефонной ширине.

## Почему SVG-DOM, а не `<canvas>`

Экспорт должен быть векторным. На SVG-холсте редактор и экспорт используют одну и ту же разметку, второй рендерер не нужен. Клик попадает по реальной форме предмета, а не по рамке. На 2–10 узлах производительность не проблема.

## Решения

- **D1.** Выгрузка через dev-плагин Figma: у REST API на тарифе Starter закончился месячный лимит.
- **D2.** Порог ΔE 8 вместо 3, иначе один оттенок вазы оставался бы сиреневым в любой схеме.
- **D3.** Шаблон хранит масштаб примера, а не долю кадра под hero. Иначе телефон на месте книги раздувало бы в 1,8 раза.
- **D4.** Hero выбирается по размеру, а не по смыслу. Иначе маленький hero оказывался мельче соседей.
- **D5.** Нижняя граница масштаба 0,6: лучше обрезать край поверхности, чем делать предметы мелкими.
- **D6.** Минимальная видимость hero взята из примеров дизайнера, а не ровные 60 %.
- **D7.** Декор не масштабируется вместе со сценой, рамка кадра не плывёт.
- **D11.** Серверная функция собирается esbuild в один файл и коммитится: Vercel ищет функции до сборки. CI проверяет, что файл свежий.
- **D13.** Наложения считаются по силуэтам с правилами стопок. Цена — до ~0,3 с на первую сборку редких сочетаний.

## Ограничения

- Rate-limit живёт в памяти одного инстанса и сбрасывается при холодном старте.
- Каталог смыслов только русский и написан вручную. Фраза вне каталога без AI даёт сцену по умолчанию.
- Шаблонов 18, все из примеров. На необычных пропорциях кадра (например, 3:1) раскладка выглядит хуже.
- Альбомное «книга + лампа + папка» разводится с касанием: для трёх предметов в этом формате есть только один шаблон.
- Силуэты включают тени, поэтому тень, заходящая на соседа, считается касанием.
